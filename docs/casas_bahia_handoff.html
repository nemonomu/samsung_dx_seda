3. 수집 단계별 흐름

  1. step00_erd_schema: ERD/schema artifact 생성 또는 갱신.
  2. step01_main_list: main listing 수집 및 listing 필드 저장.
  3. step02_main_targets: main 후보 dedupe, 최초 등장 기준 main_rank 부여.
  4. step03_bsr_list: BSR listing 수집.
  5. step04_bsr_rank: BSR 후보 dedupe, bsr_rank 1~100 생성.
  6. step07_final_targets: main/bsr merge. 중복 SKU/URL은 기존 rank를 덮어쓰지 않음.
  7. step08_detail_enrichment: PDP/detail/spec/shipping/similar/rating 보강.
  8. step09_review20: 상세 리뷰 본문 최대 20개 보강.
  9. freight_cdp_backfill: Casas 전용 배송 blank 보강.
  10. listing_badge_backfill: Casas 전용 listing badge/status/discount 보강.
  11. step15_final_output: DB용 최종 컬럼 순서와 format 변환.
  12. step16_field_audit: 필드 blank/형식/의심값 audit.
  13. step11_s3_sync: full run 기준 S3 sync.
  14. step13_db_prepare: 제품군별 DB table 생성.
  15. step14_db_load: final_output.csv DB insert.
  16. step10_status_check: 상태 점검.
  17. step12_local_cleanup: cleanup.

4. 제품군별 고유 수집 컬럼

제품군고유 컬럼수집 위치 / exact key
TVsku, screen_size, estimated_annual_electricity_use, model_yearPDP product source/spec. SKU는 Modelo, screen은 Tamanho da Tela, energy는 Consumo de energia, year는 Ano de lancamento. exact key 값은 원문 그대로 저장.
REFref_refrigerator_type, ref_capacity, sku_short_version, skuPDP product source/spec. refrigerator type은 product source exact group/key 기준. capacity는 Capacidade de armazenagem total (L) 또는 Capacidade de armazenagem total.
LDYldy_loading_type, ldy_color, ldy_capacity, sku_short_version, skuPDP product source/spec. loading은 Acesso ao cesto, color는 Cor, capacity는 Capacidade Kg de Roupas 또는 Capacidade.

5. 수집방식

  • Listing: Casas Bahia partner API api/v3/web/busca. 가격은 price_api.attach_listing_prices로 보강.
  • Detail/spec: PDP product source API api/v2/sku/source/CB, direct first. 설정에 따라 ZenRows fallback 가능.
  • Freight/pickup: freight API + pickup API 후 Casas 전용 browser/CDP blank-only 보강.
  • Listing badge: Casas 전용 listing_badge_backfill로 badge/status/discount 보강.
  • Review: PDP reviews API api/v3/reviews/product/{product_id}/source/CB, MOST_USEFUL 기준 최대 20개 수집.
  • ZenRows: product source fallback/probe 용도. 광범위 사용 전 비용 판단 필요.

7. 실행 및 브라우저 안정화

실행 BAT

파일용도순서/특징
run_casas_bahia_tv_ref_ldy_full.batCasas Bahia 단독 full runTV → REF → LDY 순차 실행.
run_magalu_casas_interleaved_tv_ref_ldy_full.batMagalu/Casas Bahia 교차 full runMagalu TV → Casas TV → Magalu REF → Casas REF → Magalu LDY → Casas LDY. 기본 대기시간은 0초.

Chrome/CDP 대응

  • Casas Bahia CDP 단계는 full-run BAT에서 SEDA_CDP_CLOSE_EXISTING_TABS=1을 기본으로 사용해 이전 실행에서 남은 CDP 탭을 정리한다.
  • CDP profile 기본 경로는 C:\tmp\seda_casas_bahia_cdp_profile이며, 일반 사용자 Chrome profile과 분리한다.
  • 공통 CDP Chrome은 auto-start 시 background/extension/sync 관련 기능을 비활성화해 RDP 장시간 실행 중 메모리 누적을 줄인다.
  • 교차 BAT는 Magalu와 Casas를 제품군 단위로 번갈아 실행해 한 retailer에 연속 부하가 몰리는 것을 줄인다.

운영 메모

  • 환경값은 repo root .env 또는 seda/.env에서 로드한다. .env는 git 관리 대상이 아니다.
  • 기본 ZIP/postal code는 01001-001.
  • exact key 정책: spec/factsheet는 부분 문자열 매칭으로 확대하지 않는다. exact key를 모르면 추가 전에 확인한다.
  • exact key value 정책: exact key에서 나온 값은 원문 그대로 저장한다. 180, 20226 같은 값도 exact key에 있으면 blank 처리하지 않는다.
  • 실행 BAT: run_casas_bahia_tv_ref_ldy_full.bat.
