# Mode 1 — pre-20260922 REST restoration

## 기준과 실행

사용자 요청에 따라 2026-09-22 이전 main 최신 커밋 **1290145 (2026-09-04)**의 Casas REST 수집 동작을 Mode 1에 복원한다. `price_identity_mismatch` 검증은 초기 REST가 아니라 **b720208 (2026-09-23)**에서 모드 분리와 함께 추가된 조건이었다.

```bat
run_casas_bahia_tv_ref_ldy_full.bat 1
```

인자 없이 실행해도 기본값은 1이다. 전체 배치는 TV → REF → LDY, 기존 Detail·업로드·DB 적재까지 진행한다. 다른 모드 1-1/2/3/4는 바꾸지 않는다.

## 복원된 동작

- `rest_legacy.fetch_search_listing`은 당시 검색 흐름을 사용한다. HTTP 200 JSON에 `products`가 있으면 가격 첨부 결과와 무관하게 listing 본문을 반환한다.
- 9월 23일에 추가한 가격 존재/가격 식별자/상품 식별자/중복/page·sort/필터 후 행 존재 검증을 Mode 1 수집 승인 조건으로 사용하지 않는다.
- 검색 URL, 요청 설정, 가격 POST, 기존 **상품 ID 우선** 가격 연결, NEXT_DATA 형태의 파서 입력과 상품군 필터·순서는 당시 동작이다. 잘못된 가격 연결을 새 알고리즘으로 보정하는 변경은 포함하지 않는다. 정확한 SKU별 가격 연결은 별도 Mode 1-1의 기능이다.
- 재시도는 `SEDA_CASAS_BAHIA_SEARCH_RETRIES + 1`, 미설정 기본값은 총 3회이다. Mode 1에는 새 하드 상한이나 배치의 재시도 값 강제 덮어쓰기를 적용하지 않는다. 대기 간격도 당시의 설정값 × 재시도 순번이다.
- `SEDA_REUSE_RAW=1`로 기존 raw를 재사용할 때 Mode 1은 가격 검증·mode sidecar 검증 없이 과거처럼 재파싱한다. 다른 모드의 가공된 raw를 Mode 1 입력으로 섞지 않는다. 새 전체 수집은 재사용을 요청하지 않는 것이 전제다.
- Casas 단독 Mode 1은 일부 페이지가 실패해도 수집행이 있으면 `main_occurrences.csv`를 저장하고 다음 단계로 진행한다. Main 300/BSR 100은 이 모드의 부분 성공 최소 조건이 아니다. 0행은 기존처럼 중단한다(`SEDA_ALLOW_EMPTY_LISTING` 명시 설정 예외는 기존 계약 유지).

## 그대로 남기는 비수집 기능

페이지 실패 로그·자동 진단 ZIP·mode 기록·실패 목록은 유지한다. 부분 결과는 `complete=false`로 표시하고 partial CSV도 보존하되, 복원된 Mode 1의 진행 판단을 막지 않는다. 예외 본문에 민감정보가 포함될 수 있으므로 당시의 원문 예외 출력은 복원하지 않고 안전한 오류 유형만 기록한다.

기존 Detail, CSV 컬럼, DB 저장/로드, 번역을 이 복원 작업에서 되돌리거나 변경하지 않는다. 이는 저장소 전체 checkout이 아니라 **Mode 1의 REST listing 및 부분 결과 진행 동작 복원**이다. 다른 모드의 엄격 검증·가격 보완·부분 성공 최소 조건은 유지한다.

## 검증 경계

1290145의 검색·가격 연결 동작을 독립 fixture로 실행하고 복원된 Mode 1과 HTTP 요청/재시도/입력 JSON/출력 행을 비교한다. TV·REF·LDY의 Main/BSR, 가격 누락·충돌·검색 실패·raw 재사용·부분 결과 저장을 오프라인으로 검증한다. 실제 외부 API/GCP의 수집 성공과 최종 데이터 정확성을 보장하는 테스트는 아니다.
