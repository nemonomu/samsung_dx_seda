# Casas Bahia 배송 대기 제한과 시간 기록

기존 우편번호와 상품·가격·재고 컬럼은 유지한다. 배송 보완에서 값이 없으면 해당 값을 만들어 넣지 않는다.

## 대기 제한

- 브라우저 내부 배송 API: 요청과 응답 본문 수신을 합해 요청당 기본 30초. 시간 초과는 배송불가로 해석하지 않는다.
- 실제 상품 페이지 배송 보완: 상품당 기본 총 40초. 페이지 이동, 품절 확인, 우편번호 입력, 버튼 조회, 응답 및 본문 수신, 재시도가 모두 포함된다.
- 첫 페이지 조회도 남아 있는 전체 예산까지 사용한다(기본 최대 40초). 재시도 시간을 미리 떼어 놓아 정상 응답을 조기 중단하지 않는다. 일시적 오류나 별도로 설정한 짧은 시도 제한으로 시간이 남으면 한 번만 재시도한다. 전체 40초를 소진하면 추가 재시도하지 않는다.
- 요청 상품 페이지에서 명시적인 품절 문구가 보이면 배송 보완만 건너뛴다. 상품을 삭제하거나 재고 컬럼을 변경하지 않는다.
- API에서 404가 확인되면 같은 실행에서 동일 상품·판매자의 페이지 배송 요청을 반복하지 않는다. 404라도 기존 파서가 유효 배송 안내를 읽은 결과는 유지한다.
- 배송 계산 오류 안내는 배송불가나 품절로 바꾸지 않는다.

시간 설정은 아래 비밀정보가 아닌 환경변수로 조정할 수 있다. 0 이하 값은 CLI에서 거부한다.

| 환경변수 | 기본값 | 범위 |
| --- | --- | --- |
| `SEDA_CASAS_BAHIA_FREIGHT_NATIVE_TOTAL_TIMEOUT_MS` | `40000` | 실제 페이지 보완의 상품당 전체 한도 |
| `SEDA_CASAS_BAHIA_FREIGHT_REQUEST_TIMEOUT_MS` | `30000` | 브라우저 배송 API의 요청·본문 한도 |
| `SEDA_CASAS_BAHIA_TIMING` | `1` | 시간 기록 사용, `0`이면 끔 |

API 요청 30초와 실제 페이지 보완 40초는 서로 다른 경로의 한도이다. 전체 수집이나 모든 API를 합쳐 상품당 40초로 제한하는 설정은 아니다. 브라우저 배치는 병렬 요청의 묶음 수에 따른 추가 한도가 있고, 브라우저 탐색 문맥 오류에 대한 기존 재시도는 유지한다. 일반 상세 API와 ZenRows 필드 보완의 수집·재시도 정책은 바꾸지 않는다.

## 기록 위치와 읽는 법

실행 날짜 폴더의 `status/casas_bahia_timing/timing_<프로세스번호>.jsonl`에 한 줄씩 저장한다. 각 프로세스는 별도 파일을 사용하고 시작·종료 이벤트를 즉시 저장한다. 로그 저장 실패 시 수집은 계속하며 고정 경고를 한 번 출력한다.

| 기록 항목 | 의미 |
| --- | --- |
| `operation` | 단계, 상세 API, 배송, 리뷰, 페이지 로딩, 응답 대기 등 작업 이름 |
| `event` | `start`: 시작, `finish`: 종료 |
| `recorded_at_utc` | UTC 기록 시각. 한국 시간은 9시간 더함 |
| `elapsed_ms` | 해당 작업의 실제 소요 밀리초 |
| `sku_id` / `seller_id` | 식별할 수 있는 경우 상품·판매자 번호 |
| `status_code` | 받을 수 있는 경우 HTTP 응답 코드. `0`은 응답 없음 |
| `attempt` / `wait_seconds` | 재시도 차수 또는 실제 대기 시간 |
| `reason` / `exception_type` | 정해진 분류의 종료 사유와 오류 종류 |
| `request_id` / `parent_request_id` | 시작·종료 및 상위 작업과 하위 요청 연결 |
| `profile` / `transport` | ZenRows 요청 유형 또는 요청 수단 |
| `http_elapsed_ms` / `http_started_at_utc` / `http_finished_at_utc` | 브라우저 배송 요청 자체의 시간. 배치가 반환된 뒤 저장됨 |
| `exit_code` | 크롤러 단계의 프로세스 종료 코드 |

종료 이벤트의 소요 시간을 비교하면 어느 요청·페이지 단계·재시도 대기에서 시간이 늘었는지 구분할 수 있다. 같은 `request_id`에 시작만 있고 종료가 없으면 실행 종료 시점의 미완료 후보이다. 이것만으로 VM이 종료된 원인까지 확정할 수는 없으므로 VM 종료 이벤트와 대조한다. 로그 기록 시점의 강제 종료·저장 실패로 일부 기록이 없을 수 있다.

HTTP 오류 코드와 오류 종류는 기록하지만 인증값, URL, 헤더, 쿠키, 응답 원문, 자유 형식 예외 메시지는 새 시간 로그에 저장하지 않는다. 기록 추가 전의 과거 요청 시간이나 사이트 내부 오류 원인을 복원할 수는 없다.

## 최종 검수 보완

- 실제 페이지 자동 응답도 상품·판매자뿐 아니라 설정 우편번호가 일치해야 채택한다. 다른 우편번호의 자동 응답은 무시하고 입력·조회한다.
- HTTP 200 자체로 배송 보완 성공을 판단하지 않는다. 배송값이 실제로 채워진 경우에만 이전 실패 기록과 집계를 정리한다.
- 일시 HTTP 오류의 재시도 사유는 해당 시도 종료 이벤트가 저장되기 전에 기록한다.

## 원격 시간 측정 후 조정

첫 30초 시험은 모두 실패했고, 그 뒤 별도 90초 시험에서는 정상 배송값을 21~26초에 받았다. 첫 시험은 시도당 20초 제한도 있었으므로 이 결과만으로 전체 30초가 충분하다고 판단하지 않는다.

사용자 요청으로 실제 페이지 보완의 기본 전체 한도와 시도당 한도를 모두 40초로 설정한다. 첫 시도를 20초에 강제로 끊지 않으며 정상 응답을 받으면 즉시 다음 상품으로 진행한다. 페이지 이동·조회·응답 본문 수신·재시도를 합쳐 상품당 최대 40초이며 재시도 때문에 추가 40초를 기다리지 않는다. 빠른 일시 오류로 시간이 남은 경우에만 한 번 재시도한다.

`SEDA_CASAS_BAHIA_FREIGHT_NATIVE_TIMEOUT_MS` 또는 `SEDA_CASAS_BAHIA_FREIGHT_NATIVE_TOTAL_TIMEOUT_MS`를 따로 설정하면 해당 설정을 적용한다. 브라우저 배송 API 요청의 기본 30초 한도는 유지한다. 로컬 수정이며 원격 서버 적용·실제 수집 검증은 별도로 필요하다.
