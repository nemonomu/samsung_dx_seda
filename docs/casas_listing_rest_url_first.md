# Casas Bahia Mode 1-1: REST API URL-first

## 선택과 범위

```bat
run_casas_bahia_tv_ref_ldy_full.bat 1-1
```

TV → REF → LDY의 기존 전체 배치를 실행한다. 기본값은 **1**이다. Mode 1은 별도 사용자 요청에 따라 `1290145`의 REST 동작으로 복원했으며 Mode 1-1에는 그 복원을 적용하지 않는다. `--resume-tv-detail`은 기존 Mode 4 전용으로 유지한다. 이 전체 배치는 dry-run이 아니며 업로드·DB 적재까지 진행한다.

## Listing

1. Mode 1의 Partner 검색 GET, 페이지 크기·정렬·지역 등 요청 설정을 재사용한다. 검색 실패 시 최대 3회(최초 포함) 시도한다. Chrome/SSR/ZenRows로 자동 전환하지 않는다.
2. Casas 상품 URL의 SKU ID를 기준으로 검색 결과를 유지한다. 페이지·정렬·URL 검증, 기존 상품군 필터 및 순서를 보존한다. 잘못된 URL·응답 문맥이나 다른 페이지와 완전히 같은 SKU 집합은 성공으로 처리하지 않는다.
3. 가격 API의 전체 offer에서 URL SKU와 확인된 상품·판매자 ID가 일치하는 가격만 연결한다. 같은 상품 ID의 다른 SKU 가격이나 다른 판매자 가격을 붙이지 않는다.
4. 가격 누락·실패·연결 불일치만 있으면 상품을 버리지 않고 가격 보류 상태로 남긴다. 가격 실패만으로 검색을 반복하지 않는다. 원천 가격이 없는 값을 계산하여 만들지 않는다.
5. 기존 main 300 / BSR 100 필터 후 unique 승인 기준과 페이지 범위를 유지한다. 임계치 도달 시 조기 종료하는 변경은 포함하지 않는다.

정상 응답은 Mode 1과 같은 파서/필터로 처리한다. 복원된 Mode 1도 가격 실패만으로 페이지를 버리지는 않지만, 당시의 상품 ID 우선 가격 연결을 그대로 사용한다. Mode 1-1은 정확한 URL SKU별 가격 연결·보류 및 별도 Detail 보완을 적용하므로, 충돌 응답의 값과 실패 상황의 진행 판정은 두 모드가 다를 수 있다. 실제 시점별 상품·가격 변동도 별도 고려해야 한다.

## Detail

- 기존 상품 상세 수집을 유지한다. 상품 source에서 확인한 ID를 이용해 판매자 의존 배송·픽업 API 호출 전에 필요한 가격·판매자 정보를 검증한다.
- 판매자가 없으면 상품 ID로 가격 offer를 조회하고 정확한 URL SKU에 대응하는 단일 offer일 때만 판매자를 채운다. 불명확한 판매자에 기본 판매자 ID를 임의 대입하지 않는다.
- 기존 값과 가격 응답이 일치하는지 확인한 뒤, 비어 있는 가격 필드만 채운다. 기존 값과 충돌하거나 후보가 여러 개면 덮어쓰지 않고 실패 사유를 남긴다.
- 동일 Detail 프로세스의 동일 상품·SKU·판매자 요청은 공유 캐시로 중복 호출하지 않는다. 초기 보완과 Detail 마지막 보완도 같은 캐시를 사용한다. 프로세스 재실행 시 캐시는 새로 시작한다.
- 현재 offer에 원가·할인 정보가 없다는 사실과 API 실패/식별 충돌을 구분한다. offer의 선택적 필드 부재를 사이트 전체에 값이 없다는 증거로 취급하지 않는다.
- API 실패나 실제 충돌은 NULL/기존 값을 유지하고 trace에 미해결 상태를 기록한다. 외부 API 오류 자체를 이 로직이 반드시 해결한다고 보장하지 않는다. 행 저장 완료를 모든 컬럼 검증 완료와 혼동하지 않는다.

## 진단과 저장 계약

- 로그/manifest/raw metadata의 모드는 문자열 `1-1`, 라벨은 `rest_api_url_first`, listing method는 `api_partner_url_first`이다. 다른 모드의 raw를 섞어 재사용하지 않는다.
- Main/BSR 종료 시 기존 log 폴더의 자동 진단 ZIP에 모드와 가격 성공/보류 개수·안전한 오류 코드를 기록한다.
- Detail `detail/trace/subcall_trace.csv`의 `casas_mode11_price_recovery`에 검증 결과와 식별자별 후보 수를 기록한다. 키·인증 헤더·원문 예외/응답을 기록하지 않는다.
- CSV 컬럼, DB 로드/저장, 공통 번역 및 기존 배송 문구 변환 계약은 변경하지 않는다.

## 검증 경계

정상 응답의 Mode 1 비교, 누락·충돌 응답, Detail 보완/재개/저장과 기존 모드 회귀를 오프라인 mock 테스트로 검증한다. 실제 사이트/GCP에서의 장시간 수집 안정성 및 모든 상품의 최종 필드 완성은 별도의 실측 검증이 필요하다.
