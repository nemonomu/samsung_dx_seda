# Casas Bahia mode 4: URL-first listing

## 변경 범위

2026-09-23 사용자 승인: **mode 4**에서 Listing은 상품 URL과 기존 상품 필터·노출 순서를 확보하면 Detail로 전달한다. 가격·판매자 응답의 누락 또는 불일치만으로 상품이나 페이지를 버리지 않는다. 2026-09-24 사용자 요청으로 현재 기본 모드는 **1 (REST API)**이며 모드 4는 명시적으로 선택할 수 있다. 기존 모드 1/2/3의 수집 로직은 그대로 유지한다. 아래 동작은 mode 4에만 적용한다.

- 판매자는 최종 CSV·DB 수집 항목이 아니다. `seller_id`는 가격·배송 API 연결을 위한 기존 내부 필드로만 유지한다.
- 상품 URL에서 확인한 SKU로 상품을 구분한다. 선택적 상품 ID/SKU 별칭이 URL과 충돌하면 의심되는 메타데이터·가격만 보류한다. 상품 ID를 URL의 SKU로 추정하지 않는다.
- 요청 페이지·명시된 정렬·중복 상품·다른 페이지의 동일 상품 집합 반복 검사는 유지한다. 기존 TV/REF/LDY 필터와 순위·중복 제거·main 300/BSR 100 기준은 변경하지 않는다.
- 가격이 확인된 상품의 값은 보존한다. 다른 상품/판매자의 가격이나 모호한 복수 가격 응답을 임의로 선택하지 않는다. 가격 누락은 빈 값 및 `casas_listing_price_pending` 상태로 남긴다.
- 기존 raw 재사용 경로도 명시적으로 충돌한 가격을 채택하지 않는다. 독립적인 프로모션·평점 등은 가격 누락 때문에 제거하지 않는다.

## 요청 흐름

1. REST 검색 또는 브라우저 검색이 성공하면 상품 URL을 확보한다. 기존 가격 요청은 유지하되 가격만 실패했다고 검색을 반복하지 않는다.
2. 모드 4는 모드 3의 검색 최대 3회 정책을 유지한다. 최종 검색 403 또는 최초 Document 403에서는 같은 Chrome의 SSR 경로로 복구한다. 가격 API만 403이면 확보한 검색 결과를 그대로 사용한다.
3. SSR은 현재 navigation의 완료된 Document에서 상품을 확보한다. 그 시점에 확보된 가격 응답은 가능한 상품에만 연결한다. 가격 응답을 기다리기 위해 페이지 성공을 막거나 추가 탐색하지 않는다.
4. 같은 Chrome의 Main→BSR 연결, 요청 간격, 키·ZenRows 정책은 그대로다. 현재 기본 모드는 1이며 인자 1/2/3/4로 실행 방식을 선택할 수 있다. 페이지 이동 중 API 호출 등 문서 일관성 오류는 가격 누락으로 숨기지 않는다.

## Detail 보완

- 기존 Detail 및 기존 보강 처리를 먼저 수행한다. 전체 PDP HTML 수집을 새로 켜지 않는다.
- 최종 가격이 여전히 비어 있고 URL SKU·상품 ID가 명확한 행에 기존 직접 가격 REST 요청을 1회 수행한다. 판매자 ID가 있으면 기존 요청을 유지한다. 판매자 ID가 공란이면 기존 API의 `produtos: [{idProduto: ...}]` 경로로 조회한다. 잘못된 nonblank 판매자 ID는 추측하거나 공란으로 간주하지 않는다.
- 상품 ID·URL SKU가 모두 일치하는 응답이 정확히 하나이고 반환 판매자 ID·가격·재고 응답의 식별값이 유효할 때만 내부 `seller_id`와 누락 가격을 함께 저장한다. 여러 판매 조건 중 최저가/첫 항목/기본 판매자를 임의로 선택하지 않는다.
- 같은 상품 ID만 조회한 결과는 동일 상품의 다른 SKU에서도 재사용하되 매 행의 URL SKU를 다시 검증한다. 판매자 지정 조회의 캐시는 별도로 유지한다. 보충 실패 시 사유를 trace에 기록하고 NULL을 보존한다. 이 변경은 상세 페이지 자동 탐색이나 유료 fallback을 새로 추가하지 않는다.
- 상품·SKU·판매자가 일치하는 가격만 사용하며 이미 채워진 가격/할인 값은 덮어쓰지 않는다. 연결 실패는 상태만 남기고 상품 행을 보존한다.
- 새로운 ZenRows 유료 경로·판매자 수집 항목·DB 컬럼은 추가하지 않는다. 기존 배송/픽업의 기본 판매자 처리도 이번 범위에서는 변경하지 않는다.
- 기존 체크포인트·트랜잭션 최종 저장·중단 후 재개를 유지한다. 가격 보완 실패만으로 정상 처리된 상품 행을 제거하지 않는다.

## 로그 및 검증 한계

- Listing 성공 로그의 `price_pending`과 진단 ZIP의 `price_pending_products`, `seller_pending_products`는 원천 상품 기준 숫자다. 기존 관련성 필터 적용 후 출력 행 수와 다를 수 있다.
- 원래 가격 API의 실패 상태와 Listing 성공 상태를 함께 기록한다. 응답 본문·키·쿠키는 진단에 포함하지 않는다.
- 검증은 외부 통신/브라우저/DB/업로드를 차단한 오프라인 테스트다. 실제 GCP 수집 성공이나 모든 가격의 채워짐을 검증한 것은 아니다.

## 2026-09-23 TV Detail 재개 후 REF/LDY 연속 수집

GCP에서 수정본 반영 및 필요한 Python 패키지 설치 후 기존 배치에 재개 인자를 준다.

```bat
run_casas_bahia_tv_ref_ldy_full.bat 4 --resume-tv-detail 20260923 308
```

TV의 저장된 308행을 복원해 누락 가격 보충 및 후속 단계를 수행하고, 성공하면 REF 전체, 이어서 LDY 전체 수집을 실행한다. 세 품목 모두 20260923 실행 날짜를 사용한다. 어느 품목이든 실패하면 다음 품목을 실행하지 않는다. 인자 없는 기존 전체 실행과 모드 1/2/3/4 선택 방식은 그대로다.

- 대상은 기존 GCP 실행 폴더 `seda/data/casas_bahia/tv/20260923`의 308행이다. references에 복사한 파일이 아니라 원래 실행 폴더의 대상 CSV, enriched CSV, 정규 trace를 사용한다.
- `SEDA_RUN_DATE=20260923`과 `SEDA_FORCE_DATED_RUN_ROOT=1`로 날짜를 고정하고, TV/REF/LDY 각 품목 인자에 따라 실행 폴더를 다시 계산한다. 이전 품목의 실행 폴더를 재사용하지 않으며 날짜가 바뀌었다고 20260924 폴더에서 재시작하지 않는다.
- `SEDA_DETAIL_SKIP=308`은 기존 308행을 검증해 복원하고 상품별 Detail 루프를 건너뛴다. `SEDA_DETAIL_LIMIT=0`, worker ID 공란, shipping-only 모드 0을 사용한다. 대상/출력 CSV override는 원래 실행 폴더로 지정한다.
- TV 재개에서만 `SEDA_CASAS_BAHIA_ZENROWS_FIELD_FALLBACK=0`으로 이미 실패한 유료 필드 보충을 반복하지 않는다. Mode 4의 `SEDA_CASAS_BAHIA_API_ENRICH=1` 가격 보충은 유지한다.
- TV orchestrator의 정확한 시작 옵션은 `--product-line TV --from-step detail_enrichment --skip-local-cleanup`이다. 가격 보충 뒤 기존 배송비·리뷰·할인·최종 출력·DB 단계로 이어진다. TV Main/BSR과 기존 308개 Detail 호출은 재수행하지 않는다. REF/LDY는 각각 `--all`로 처음부터 수집한다.
- TV 전용 재개 설정은 중첩 `setlocal` 범위에 한정한다. 상속된 skip/worker/TV CSV 경로도 재개 모드 시작 시 정리하여 REF/LDY로 넘기지 않는다. REF/LDY의 ZenRows 필드 보충은 TV에서 일시 중지하기 전 기존 배치 설정으로 복원한다. 배송 우편번호 등 기존 업무 설정은 유지한다.
- 원래 파일의 행 수·순서·헤더·trace 검증 실패는 우회하지 않는다. 실행 전 해당 파일들이 존재하는지 확인한다. 기존 체크포인트/트랜잭션 저장을 재사용한다.
